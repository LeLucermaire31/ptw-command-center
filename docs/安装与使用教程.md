## 一、应用概述

PTW Command Center 是 PTW 2.0 力量举新手计划的训练指挥中心。它替代了传统的 Excel 表格，自动计算每次训练的加重幅度、判断卡壳退阶、管理轻/重日循环。

**技术特性：**
- 单 HTML 文件，无需安装任何 App
- 数据存储在浏览器 LocalStorage，完全离线可用
- PWA 支持，可添加到手机/电脑主屏幕
- 适配手机屏幕，移动端优先设计

**训练计划覆盖范围：**
- Phase 1（纯新手阶段）：每周 3 天恒定训练
- Phase 2（进阶新手阶段）：H-L-H 轻重日循环
- Phase 3（中级阶段）：RPE 驱动，预留接口

## 二、Windows 电脑安装

### 方式一：直接打开（推荐日常使用）

1. 双击 `index.html` 文件，浏览器自动打开
2. 开始使用

**优点：** 简单直接
**缺点：** Service Worker 在 `file://` 协议下不可用，无法离线缓存

### 方式二：本地 HTTP 服务器（推荐，启用 PWA）

打开终端，在 `index.html` 所在目录执行以下任一命令：

**使用 Node.js（首选）：**
```bash
npx serve -p 3333 -s .
```
然后浏览器访问 `http://localhost:3333`

**使用 Python 3：**
```bash
python -m http.server 3333
```
然后浏览器访问 `http://localhost:3333`

**优点：** PWA 完整功能、离线缓存可用、地址栏干净

### 方式三：安装为桌面 PWA（Edge / Chrome）

1. 用浏览器打开 `index.html`（需通过 HTTP 服务器方式）
2. 点击地址栏右侧的"安装"图标（⊞ + ↓），或菜单 → 应用 → 将此站点作为应用安装
3. 桌面会生成 PTW Command Center 图标
4. 以后双击图标即可打开，独立窗口运行

**效果：** 无浏览器地址栏，像原生应用一样运行

## 三、Android 手机安装

### 步骤 1：启动电脑端 HTTP 服务器

在电脑终端执行：
```bash
npx serve -p 3333 -s .
```
记录电脑局域网 IP 地址：

**Windows：**
```bash
ipconfig | findstr "IPv4"
```
通常为 `192.168.x.x` 格式。

### 步骤 2：手机浏览器访问

1. 确保手机与电脑连接**同一 WiFi**
2. 手机浏览器打开：`http://192.168.x.x:3333`（替换为实际 IP）
3. 页面正常显示后继续

### 步骤 3：添加到主屏幕

**Chrome / Edge 安卓版：**
1. 打开 `http://192.168.x.x:3333`
2. 等待 Service Worker 注册完成（页面完全加载后约 1-2 秒）
3. 点击浏览器菜单（右上角 ⋮）
4. 选择"添加到主屏幕"或"安装应用"
5. 确认安装

**Firefox 安卓版：**
1. 地址栏会出现一个"主页+"图标
2. 点击即添加到主屏幕

**效果：** 手机桌面出现 PTW 图标，点击后全屏运行，无浏览器工具栏。

### 后续使用

安装到桌面后，手机断网也能打开使用（Service Worker 已缓存全部资源）。训练数据保存在手机浏览器 LocalStorage 中。

**注意：** 每次需要用到 PWA 缓存的内容时，确保首次加载时有网络连接以便 Service Worker 拉取最新资源。

---

### 长期方案：部署到静态托管

如果不想每次手动启动 HTTP 服务器，可以把 `index.html` 部署到免费静态托管服务：

| 平台 | 方式 |
|------|------|
| **GitHub Pages** | 上传到仓库 → Settings → Pages 开启 |
| **Cloudflare Pages** | 拖拽文件到控制台 |
| **Netlify Drop** | 访问 app.netlify.com/drop 直接拖入 `index.html` |
| **Vercel** | `npx vercel .` 一键部署 |

部署后会得到固定 URL（如 `https://xxx.netlify.app`），手机直接访问并添加到主屏幕即可。

## 四、首次使用：Onboarding

首次打开应用，会进入 Onboarding 引导流程。

### 4.1 录入三项数据

三步式表单，依次录入 **深蹲、卧推、硬拉** 的：

1. **上次训练重量（kg）** — 你最近一次成功完成训练的杠铃重量
2. **当前阶段** — Phase 1（纯新手）或 Phase 2（进阶新手）

### 4.2 阶段选择参考

| 条件 | 选择 |
|------|------|
| 刚开始力量训练 | Phase 1 |
| 深蹲 < 1.5 倍体重 | Phase 1 |
| Phase 1 期间出现过卡壳（任一组 < 3 次） | Phase 2 |
| 已有线性加重训练经验 | Phase 2 |

### 4.3 完成 Onboarding

三个动作全部录入后点击"开始训练"，进入主界面。数据自动保存到 LocalStorage。

## 五、Dashboard 仪表盘

Dashboard 是应用的首页，展示三动作的状态卡片。

### 5.1 卡片信息解读

每张卡片显示：

| 字段 | 含义 |
|------|------|
| **Phase 徽章** | 当前训练阶段（P1 / P2 / P3） |
| **重量** | 上次训练重量（kg），含 .0/.5 尾数 |
| **目标次数** | 下次训练最低需完成的总次数 |
| **训练次数** | 当前阶段已完成的训练次数 |
| **阶段标签** | 恒定日(P1) / 轻重日循环(P2) |

### 5.2 targetMinReps 说明

targetMinReps 是**动态目标**。它可能高于初始下限（sets × 3），因为：

- 上次训练落在 Min 区间 → 不加重，但 targetMinReps + 1
- P2 Bench Mid 区间 → targetMinReps + 2
- 正常加重后 → targetMinReps 重置为 sets × 3

上限为 sets × 6（每组最多 6 次），不会无限增长。

## 六、Session 训练课表

点击底部 **Session** 标签进入当天训练。

### 6.1 课表显示

页面顶部显示：
- 当天课表类型（P1 恒定日 / Heavy 重日 / Light 轻日）
- 各动作的训练组数
- 热身方案

### 6.2 热身计算

每个动作独立生成 4 组热身：

| 百分比 | 次数 | 说明 |
|--------|------|------|
| 50% | 8 次 | 空杆/轻重量激活 |
| 70% | 5 次 | 中等重量过渡 |
| 80% | 3 次 | 接近工作重量 |
| 90% | 2 次 | 神经适应性热身 |

所有热身重量自动取整到 0.5kg。

### 6.3 正式组录入

点击"开始训练"进入数据录入界面。每个动作依次展示：

1. **重量输入框** — 默认填入上次训练重量
2. **组数据表格** — 每行包含：
   - 组号
   - 次数（必填）
   - RPE（可选，仅用于日志记录，不参与 P1/P2 算法）

### 6.4 RPE 颜色辅助

RPE 输入框根据数值显示对应颜色（仅视觉辅助）：

| RPE | 颜色 | 含义 |
|-----|------|------|
| 7 ~ 8 | 绿/蓝 | 还有 2-3 次余力 |
| 8.5 ~ 9 | 黄/橙 | 还有 1 次余力 |
| 9.5 ~ 10 | 红 | 力竭 / 极限 |

### 6.5 提交训练

完成所有组的数据录入后点击"提交"。应用自动：

1. 计算每组总次数
2. 判定次数区间（missed / min / mid / maxed）
3. 检查是否卡壳（任一组 < 3 次）
4. 计算下次训练重量 + 目标次数
5. 写入训练日志
6. 刷新 Dashboard 数据

### 6.6 Light Day 注意事项

P2 阶段每第 3 次训练为 Light Day（sessionCount % 3 == 2）：

- 仅做停顿深蹲 + 停顿卧推（各 2 组）
- 无硬拉训练
- **重量不变，不触发加重/卡壳判定**
- 目的是技术打磨和主动恢复

## 七、Log 训练日志

点击底部 **Log** 标签查看历史训练记录。

### 7.1 日志列表

按日期倒序显示，每条包含：
- 日期和时间
- 课表类型（P1 / Heavy / Light）
- 各动作总次数 + 区间判定
- 卡壳标记（如有）

### 7.2 展开详情

点击任意日志条目展开，显示：
- 每组详情（重量 × 次数 × RPE）
- 总次数汇总
- 区间判定结果

### 7.3 编辑日志

展开日志后点击"编辑"按钮：
- 可修改每组次数和 RPE
- 可修改重量
- 保存后数据更新到 LocalStorage
- **注意：编辑历史不会触发算法重新计算，仅修正记录数据**

### 7.4 删除日志

展开日志后点击"删除"按钮：
- 弹出确认对话框
- 确认后永久删除（不可恢复）

## 八、Settings 设置

点击底部 **Settings** 标签进入设置面板。

### 8.1 参数调整

每个动作可独立修改：
- **当前重量** — 直接输入新重量（自动取整到 0.5kg）
- **阶段** — 切换 P1/P2/P3
- **目标最低次数** — 手动调整 targetMinReps

### 8.2 重新 Onboarding

点击"重新开始"按钮：
- 清空所有训练数据
- 清除训练日志
- 回到 Onboarding 流程

### 8.3 数据清除

- **清除日志**：仅删除训练日志，保留动作配置
- **全部重置**：清除所有数据，回到初始状态

## 九、训练算法详解

### 9.1 次数区间判定（4 级）

| 区间 | 条件 | 含义 |
|------|------|------|
| **missed** | totalReps < targetMinReps | 未达动态目标，不加重，目标不变 |
| **min** | totalReps == targetMinReps | 刚好达标，维持重量，targetMinReps +1/+2 |
| **mid** | targetMinReps < totalReps < maxReps | 超额完成，按矩阵加重 |
| **maxed** | totalReps >= maxReps (sets × 6) | 拉满上限，最大幅度加重 |

### 9.2 上下肢加重矩阵

**下肢 (Squat / Deadlift)：**

| 阶段 | Min | Mid | Maxed |
|------|-----|-----|-------|
| P1 | +0 kg, target+1 | +2.5 kg | +5.0 kg |
| P2 | +0 kg, target+1 | +1.0 kg | +2.5 kg |

**上肢 (Bench)：**

| 阶段 | Min | Mid | Maxed |
|------|-----|-----|-------|
| P1 | +0 kg, target+1 | +1.0 kg | +2.5 kg |
| P2 | +0 kg, target+1 | +0 kg, target+2 | +1.0 kg |

### 9.3 双重递增法

核心原则：**Min 区间不加重，改为提升 targetMinReps**。

- 如果上次刚好踩线（Min），说明重量刚好合适，不用加
- 但要求下次多做 1-2 次总次数
- 直到某次突破 Min 进入 Mid/Maxed 才真正加重

### 9.4 即时熔断（Stall）

触发器：**任意一组次数 < 3**

效果：
1. 重量立即降至 90%（floor to 0.5kg）
2. 阶段 +1（P1→P2→P3）
3. 训练次数归零
4. targetMinReps 重置为 sets × 3

这是一个**即时发生的判断**，不需要等 3 次失败。

### 9.5 杠铃片限制

所有重量强制 floor to 0.5kg：
- `89.7 → 89.5`
- `89.9 → 89.5`
- `51.1 → 51.0`
- `90% 退阶：90 × 0.9 = 81 → 81.0`

这样可以确保杠铃实际可配重（使用 1.0 / 2.5 / 3.5 / 5.0 kg 杠铃片）。

### 9.6 轻重日循环（Phase 2）

Phase 2 使用 `sessionCount % 3` 决定课表类型：

| sessionCount | 课表 | 说明 |
|--------------|------|------|
| 1, 4, 7... | Heavy | 高容量，全部三动作 |
| 2, 5, 8... | Light | 低容量，仅停顿变式，无硬拉 |
| 3, 6, 9... | Heavy | 高容量，全部三动作 |

模式：**H-L-H → H-L-H → ...**

## 十、常见问题

### Q1：重量为什么自动变成 .0/.5 结尾？

这是杠铃片限制机制的自动取整。只在现有杠铃片范围内给出可实际配置的重量。

### Q2：为什么没加重但目标次数提高了？

落在了 Min 区间。这是"双重递增法"的工作方式——先提高次数要求，下次再做更多就进入加重区间。

### Q3：卡壳了重量直接掉 10%，对劲吗？

对的。PTW 2.0 的设计哲学是：与其死磕大重量导致动作变形和受伤风险，不如果断减重，换个阶段重新积累。

### Q4：数据存在哪里？换手机会丢吗？

数据存储在浏览器的 LocalStorage 中。换手机/换浏览器后数据不会自动迁移。

**手动迁移步骤：**
1. 旧设备：Settings → 逐个记录参数，或使用浏览器开发者工具导出 `localStorage["ptw_lifts"]` 和 `localStorage["ptw_history"]`
2. 新设备：相应导入

### Q5：离线能用吗？

能。通过 HTTP 服务器首次访问后，Service Worker 缓存所有资源（HTML + CDN 脚本 + CSS）。之后完全断网也能打开训练和录入。

### Q6：能不能打包成 APK？

可以。项目预留了 Capacitor 接口。使用 Capacitor 包装后可直接构建 APK：

```bash
npm install @capacitor/core @capacitor/cli
npx cap init "PTW Command Center" "com.ptw.commandcenter"
npx cap add android
# 将 index.html 放入 www/ 目录
npx cap sync
npx cap open android
```

在 Android Studio 中 Build → Build APK。

### Q7：Phase 3 怎么用？

Phase 3（中级阶段）目前展示 RPE 驱动的 e1RM 计算界面。完整的中级 DUP 编程（每日波动周期化）将在后续版本实现。
