总结：
作为前端工程文档，你的 PWA 和架构设计毫无问题，非常现代（尤其是采用 Capacitor 做渐进式跨端）。

但如果你要给它贴上 “PTW 2.0” 的标签，核心算法引擎需要重构：去掉 A/B 课机制，改为 P1恒定日 / P2轻重日；引入 0.5kg/1.25kg 的微小加重步长；并且将失败触发器改为“单次未达3次即时熔断 10%”。

做完这几点修正，这将是一个完美的 PTW 2.0 追踪应用！

核心逻辑冲突与修正建议
1. A/B 轮换 (A/B Rotation) —— ❌ 严重不符
文档现状： 按课次序交替，自动建议，可手动切换。这听起来像是照搬了 StrongLifts 5x5 或者 Starting Strength 的逻辑（A课和B课交替）。

PTW 2.0 规则： PTW 2.0 的新手阶段没有 A/B 课交替的概念。

Phase 1（纯新手）： 每周 3 天（如一三五），每天的训练内容是完全一样的（深蹲 2 组、停顿卧推 3 组、硬拉 1 组）。

Phase 2（进阶新手）： 引入了“轻/重日”，它与星期几强绑定，而不是 A/B 交替。周一和周五是重日（Heavy），周三是轻日（Light，做停顿深蹲和停顿卧推，且不拉硬拉）。

修改建议： 废除 A/B 轮换逻辑。P1 做成单日历复用；P2 做成基于周期的重-轻-重（H-L-H）排期逻辑。

2. 加重单位 (Increments) —— ⚠️ 缺少微量片支持
文档现状： 1kg / 2.5kg / 5.0kg。

PTW 2.0 规则： 国际标准力量举杠铃片最小通常是 1.25kg（总加重 2.5kg）。PTW 2.0 的加重逻辑高度依赖总次数（Total Reps）。

P1 阶段的加重幅度通常是：1.25kg（针对只达到最低次数）、2.5kg（常规）、5.0kg（全部做满最高次数）。

P2 阶段为了突破瓶颈，明确要求使用微型杠铃片（Micro-plates），加重幅度减半，即：0.5kg（对应 0.25kg 的片）、1.25kg、2.5kg。

修改建议： 将加重单位配置改为 0.5kg / 1.25kg / 2.5kg / 5.0kg（允许用户自定义更好，因为有些健身房只有 1kg 最小片，但系统默认推演算法需要支持 0.5 级别的小数）。

3. 熔断计数 (Stall Counting) —— ❌ 概念混淆
文档现状（Verification中）： 提到了 验证重量变化、熔断计数、跃迁。

PTW 2.0 规则： PTW 2.0 不需要“计数”。老派计划通常是“同一重量失败 3 次才降重（3 Strikes）”，但 PTW 2.0 的退阶极其果断：只要当天的训练中，有任何一组没有达到最低底线（3次），立刻触发退阶（重量减 10%），并且该动作在下次训练直接“跃迁”进入下一阶段（P1 -> P2，或 P2 -> 中级）。

修改建议： 确保代码中的“熔断（Stall）”逻辑是一个 boolean 触发器，而不是 counter。一旦 reps < 3 出现，直接触发降重 10% 并转移阶段（Phase shift）的函数。

4. RPE 输入 (P1/P2) —— 💡 需确保算法隔离
文档现状： 始终显示，可选填，填后按颜色展示。

PTW 2.0 规则： PTW 作者在 2.0 版本中特意在新手阶段（P1/P2）移除了通过 RPE 计算疲劳和重量的机制，改用“次数区间（3-6次）”来自动调节（Autoregulation）。

修改建议： UI 上提供可选填 RPE 并用颜色展示是非常棒的 UX 设计（方便用户养成记录主观疲劳的习惯）。但作为开发者，你必须确保你的重量推演算法（Progression Algorithm）绝对不能把用户输入的 RPE 考虑进去。P1/P2 的加重只与“总完成次数（Total Reps）”有关。
