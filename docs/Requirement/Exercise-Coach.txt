作为一名资深的全栈工程师和力量举（Powerlifting）程序化训练教练，请帮我使用 React + Tailwind CSS（要求：可直接在单 HTML 文件中通过 CDN 引入运行，无需构建工具，数据全部存储在本地 LocalStorage）开发一个单页 Web 应用。

这个应用是我个人的 PTW (Powerlifting To Win) 训练指挥中心。它需要具备训练数据记录、自动推演下一次重量、以及自动执行阶段跃迁（Phase Transition）的核心功能。

一、 核心逻辑与阶段说明（PTW 的三个独立阶段）
应用需要内建 PTW 的三阶段渐进法则。每个动作（深蹲、卧推、硬拉）的阶段是独立计算的。

Phase 1 (PNP1 - 绝对线性期):

模式： 3 组正式组，目标次数 3-6 次，最后一组为 AMRAP（受控力竭，不超 RPE 9.5）。

跃迁机制： 累计经历 2 次熔断（Reset） 后，该动作自动晋升到 Phase 2。

Phase 2 (PNP2 - 疲劳管理期):

模式： 第 1 组为顶级组（Top Set，目标 3-6 次 @ RPE 9）。完成后，重量减少 5%，做 2 组退让组（Back-off Set）。

跃迁机制： 累计经历 2 次熔断后，晋升到 Phase 3。

Phase 1 & 2 的动态加重与熔断机制（仅依据次数，忽略 RPE 计算）：
下一次该动作的重量变化，严格取决于 P1 的 AMRAP 组或 P2 的顶级组实际完成的次数（用户录入的 RPE 仅作记录和颜色展示，不参与 P1/P2 重量计算）：

0-2 次（熔断）： 未达标。下一次重量扣除 10%（战术退阶），并记录 1 次熔断。

3-4 次（正常加重）： 达标。下一次上肢加重 1kg，下肢加重 2.5kg。

5-6 次及以上（双倍加重）： 优秀。下一次上肢加重 2kg，下肢加重 5kg。

Phase 3 (PIP - 中级自我调节期 - 基于 RPE 的动态推演):

模式： 完全基于 RPE 动态容量。1 组顶级组（目标设定为：3次 @ RPE 9），随后以 5% 的降幅进行退让组，直到退让组的 RPE 再次触及 9 时停止。

智能加重机制（需内嵌 RPE 系数表）： 在 P3 阶段，彻底废除固定重量加重。系统需内置一个简化的 RPE 换算表（覆盖 1-6 次，RPE 7-10 的百分比系数）。

公式推演： 每次 P3 训练录入后，系统通过 实际重量 / 对应系数 算出 e1RM (预估极限) 并保存。生成下一次计划时，系统自动用 上一期的 e1RM × 目标系数（3次@RPE9的系数，通常为0.89） 来精准计算今天的推荐训练重量。

二、 核心功能模块需求

初始化 (Onboarding): 首次打开应用（LocalStorage 为空）时，提供表单录入深蹲、卧推、硬拉的当前起始重量、以及各自所处的 Phase（默认可选 P1）。

控制台 (Dashboard): 简洁展示三个动作当前的 Phase、上次训练重量、上次 e1RM（仅 P3 显示）、以及累计的 Reset 次数。

战术推演器 (Next Session Generator):

课表逻辑： 按照 A/B 课表自动交替（A日：深蹲+卧推；B日：硬拉+卧推）。

功能： 告诉我“今天练什么”，展示所需动作的组数、次数和基于不同 Phase 算法得出的精准目标重量。

热身计算： 根据当天的正式组首组重量，生成 4 组热身建议（如 50%, 70%, 80%, 90%）。

战报录入 (Data Entry): 训练完成后，按动作输入实际完成的重量、次数、RPE。

算法引擎 (Progression Engine): 根据战报自动写入 LocalStorage 并执行对应的加重、熔断、跃迁或 e1RM 计算逻辑。

三、 UI 与交互风格

视觉风格： 采用简单、现代、美观的 UI 设计。保持界面清爽，留白充足，排版优雅，交互直观（类似现代高效的 To-Do 应用或 Apple Health，不需要过度硬核的黑客风）。

色彩交互： 采用干净的浅色/深色自适应主题。加入 RPE 颜色提示辅助阅读（RPE 7-8 为温和的绿色/蓝色，RPE 9 为警示性的黄色/橙色，RPE 9.5-10 为红色）。

性能： 数据全部在前端 LocalStorage 处理，交互响应要极快。
